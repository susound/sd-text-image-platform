### 2.2 AI 策略层

| 方向 | 实现类 | 类型 | 依赖 |
|------|--------|------|------|
| 文生图 | `LocalModelText2ImageProvider` | 本地 GPU（diffusers） | Python 推理服务 :5000 |
| 图生文 | `QwenImage2TextProvider` | 千问 DashScope API | 阿里云 API Key |

**架构特点：** 策略模式 — `Text2ImageProvider` / `Image2TextProvider` 双接口，通过 `AiProviderManager` 统一管理。

### 2.3 推理服务（Python FastAPI）

| 端点 | 功能 |
|------|------|
| `GET /health` | 健康检查 + 模型信息 |
| `GET /models` | 扫描 sd-models 目录 |
| `POST /generate` | 文生图推理（SD 1.5 safetensors） |
| `GET /progress/{task_id}` | 实时扩散步数进度 |

**技术要点：**
- torch 2.5.1+cu124，RTX 4060 Laptop 8GB，fp16 推理约 3.7GB
- 线程锁保护 pipeline 切换
- `lifespan` 异步启动管理器
- CUDA 异步死锁修复：`CUDA_LAUNCH_BLOCKING=1`
- 支持 6 种采样器（Euler / Euler a / DPM++ 2M Karras / DPM++ SDE Karras / DDIM / UniPC）

## 三、架构决策记录（ADR）

| 决策 ID | 决策 | 方案 | 替代方案 | 理由 |
|---------|------|------|---------|------|
| ADR-001 | 文生图 Provider | 本地 GPU 推理（diffusers + safetensors） | 云端 API（SiliconFlow/智谱） | 零 API 成本、离线可用、数据不外传 |
| ADR-002 | 图生文 Provider | 千问 Qwen3.5-Omni-Plus API | 本地 VLM 模型 | 本地 VLM 显存不够（RTX 4060 8GB 已用于 SD） |
| ADR-003 | AI 策略模式 | `Text2ImageProvider` / `Image2TextProvider` 双接口 | 硬编码调用 | 开闭原则，支持未来扩展新 Provider |
| ADR-004 | 数据库 | H2（开发）/ MySQL（生产） | 仅 MySQL | H2 开发零配置，MySQL 生产高可用 |
| ADR-005 | 前端状态管理 | Pinia | Vuex | Pinia 更轻量、TypeScript 友好 |
| ADR-006 | 认证方案 | JWT 无状态 + Spring Security | Session + Redis | 无状态便于水平扩展，减少 Redis 依赖 |
| ADR-007 | 推理服务通信 | OkHttp 同步 HTTP | 消息队列 / gRPC | 文生图为同步请求-响应模式，HTTP 最简 |
| ADR-008 | 配置管理 | DB 优先 + YAML 兜底 | 仅配置文件 | 支持管理后台运行时修改，无需重启 |
| ADR-009 | CUDA 死锁修复 | `CUDA_LAUNCH_BLOCKING=1` | 升级 torch | 环境变量修复立竿见影，torch 2.6+ 尚未验证 |
| ADR-010 | 抛弃云端 Provider | 删除所有云端 API Provider + ComfyUI | 保留部分 | 简化架构，聚焦本地推理核心能力 |

## 四、关键问题与解决方案

### 4.1 已解决的问题

| 问题 | 根因 | 方案 | 影响 |
|------|------|------|------|
| 后端 JAR 路径 Bug | `start.bat` 路径拼接错误（`%%~nxf` → `%%f`，缺 `target\`） | 修复路径变量 | 后端闪退，无法启动 |
| CUDA 异步死锁 | torch 2.5.1+cu124 + CUDA 13.2 驱动不兼容 | `CUDA_LAUNCH_BLOCKING=1` 环境变量 | 推理服务卡死无响应 |
| H2 锁文件残留 | 异常退出后 `.lock.db` 未清理 | `start.bat` 启动前自动删除 | 数据库无法连接 |
| 评估 `%` 未转义 | `String.formatted()` 中字面 `%` 导致异常 | `%` → `%%` | 评估功能始终失败 |
| 调度器缓存污染 | 生成后未恢复原始 scheduler | 生成后 restore 原始 scheduler | 多轮生成参数串扰 |
| 同级种子重复 | `System.currentTimeMillis()` 同秒重复 | `time.time_ns()` | 同秒多任务种子冲突 |
| 前端组件编译错误 | DashboardView `fetchStats` 缺 `}`；Text2ImageView 箭头函数缺 `}` | 补全闭合符号 | Vite 编译失败 |
| 推理服务信号量泄漏 | Windows Ctrl+C 无法正确清理子进程 | `stop.bat` 端口匹配强杀 | 端口占用无法重启 |
| SQL 日志刷屏 | MyBatis-Plus `StdOutImpl` 输出所有 SQL | 改用 `Slf4jImpl` + WARN 级别 | 开发日志可读性 |

### 4.2 待解决的风险

| 风险 | 等级 | 说明 | 建议 |
|------|:----:|------|------|
| 无单元测试覆盖 | 🔴 高 | 全部 Service / Controller 层无 JUnit 测试 | 第二轮优先补齐 |
| 千问 API Key 手动配置 | 🟡 中 | 需管理员登录后台手动填写，首次使用门槛高 | 增加引导提示 / 环境变量兜底 |
| 推理服务单点故障 | 🟡 中 | 单进程单 GPU，无容错 | 后续可考虑多副本 + 任务队列 |
| 前端硬编码 API 地址 | 🟡 中 | `request.js:6` 写死 `http://localhost:8080/api` | 应该全走 Vite proxy |
| 图片存储无清理机制 | 🟢 低 | `uploads/` 目录持续增长无自动清理 | 增加定时任务 / 存储配额 |
| Docker GPU 兼容性 | 🟢 低 | Windows 下 Docker GPU 透传未验证 | 仅 Linux 生产环境已验证 |
